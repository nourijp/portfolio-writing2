Technical WritingSupport Guide

Report a Software Problem Clearly

A troubleshooting handoff that helps a user gather useful evidence.

Audience Employees requesting application support

Adapted portfolio sample using a fictional product and scenario.

A useful support request explains what you tried to do, what happened, and where the process stopped.

Check the service status

If your organization provides a service-status page, check it for an incident that matches your problem. An existing incident may already explain the interruption.

Record what happened

Include the following information in your request.

  • Task — What were you trying to accomplish?
  • Location — Which page or feature were you using?
  • Steps — What did you select immediately before the problem occurred?
  • Expected result — What did you expect the application to do?
  • Actual result — What appeared instead? Include the exact error message if available.
  • Scope — Does the problem affect one record, several records, or the entire application?

Add a useful screenshot

Capture the error and enough of the surrounding screen to identify the feature. Remove personal information, customer details, and confidential records before sharing the image.

Explain the impact

State whether the problem prevents you from completing a task or whether you have a temporary way to continue. This gives the support team context for assessing the request.
